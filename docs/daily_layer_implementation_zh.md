本项目回测一个**按虚拟雪球的 delta 持有 IC 期货头寸**的策略：在给定区间上滚动发行虚拟雪球，每只在发行日按条款定出票息，此后逐日用定价模型重算 delta 并调整期货仓位，净值由期货端逐日盯市损益累计而成。

发行方式（2026-08-11 起）默认为**槽位制 ladder**：4 个发行槽位按周错峰、并行滚动，任一时点最多 4 只雪球并存，组合是一只净值化基金（一条净值、一个期货账户，逐腿 delta 聚合后一次调仓、净额计费）；条款采用**周网格日历**（周一发行、每 4 周的周五观察，104 周存续）。换月默认采用**多天展期**（`roll_window_days=5`）：每次换月平摊到 5 个交易日、每日移仓 1/5，窗口内新旧合约同时持有、损益逐合约独立盯市（当月/次月/当季倒推分批、完成日不变；下季自新合约上市日起分批），机制见 `futures_chain.build_schedule` 与 `hedger.py` 的两切片记账。`n_slots=1` 退回单链条顺序滚动；`n_slots=1, weekly_terms=False, monday_issue=False, roll_window_days=1` 与历史版本逐日恒等。机制详见 `backtest.py` 与 `hedger.py` 的模块 docstring；本 README 的 §5~§8 仍按单链条、单日换月行文，新机制的细节以代码 docstring 为准（后续更新）。

本文档按**实际回测的调用顺序**组织，说明每一步的代码位置、接口，以及所采用的数学处理与建模假设。文档定位是代码实现的说明与论证，不包含对市场行为或策略收益来源的判断。

## 0. 策略定义与代码分层

### 0.1 回测对象的形式化定义

设虚拟雪球的条款为 $\mathcal{C}$，票息 $C^*$ 由定价模型在发行日 $t_0$ 反解并锁定（见 §5.1）。此后每个交易日收盘时执行**两个动作，顺序不可交换**：

> **① 先用昨日持仓结算今日损益 → ② 再按今日目标敞口调整持仓**

这个顺序即是"无前视偏差"的实现：今日的 delta 由今日收盘价算出，只作用于**今日之后**的损益；今日的损益完全由昨日已建立的持仓决定。以下逐项展开。

#### （一）每日 IC 头寸

定价层输出的是 $\partial V/\partial S$，单位为"每指数点"（因 $V$ 以名义本金 $=1$ 归一化）。要变成无量纲的**敞口比例** $\Delta_t$（如 0.82 表示 82% 名义本金的多头），须乘一个价格：

$$
\Delta_t = \left.\frac{\partial V}{\partial S}\right|_{S = S_t} \cdot S_t
$$

其中 $V$ 是雪球在 $t$ 日、给定敲入状态下的价值函数（敲入与否决定读取 $V_{out}$ 还是 $V_{in}$ 曲线），$\partial V/\partial S$ 由 PDE 一次求解直接给出（见 §5.3）。$\Delta_t$ 即"美元 delta 占名义本金的比例"，归一化用**当日现价** $S_t$——与下一步按当日结算价换算手数的口径一致，两者相乘除后恰好还原出复制对冲所需的头寸。

敞口比例转成实际手数：

$$
N_t = \text{round}\!\left(\ \Delta_t^{\,\text{cap}} \cdot \frac{\text{名义本金}}{\text{settle}_t \times 200}\ \right)
$$

| 符号                        | 含义                                                                                                                                                             |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| $\Delta_t^{\,\text{cap}}$ | 经`delta_cap` 对称截断后的敞口比例（不截断时即 $\Delta_t$）                                                                                                  |
| $\text{settle}_t$         | **当日应持有合约**（$\text{code}_t$）的结算价——换月日即新合约的价格，因为这是实际建仓的成交价基准                                                      |
| 200                         | IC 合约乘数（元/点），故$\text{settle}_t \times 200$ = 一手的名义金额                                                                                          |
| $\text{round}(\cdot)$     | 取整到整数手。**回测默认 `round_lots=False`（编指数口径）**：持仓为连续合约数、不施加 $\text{round}$，乘数 200 在净值中自动消去；`True` 为执行层口径 |

举例：名义本金 1 亿、$\Delta_t = 0.82$、指数与期货约 6664 点，连续口径下持仓 $= 0.82 \times 10^8 / (6664 \times 200) = 61.52$ 张合约；执行层口径（`round_lots=True`）取整为 62 手，取整带来的敞口误差上限为半手，即 $0.5 \times 6664 \times 200 / 10^8 = 0.67$ 个敞口百分点——这个量级与模型误差的对比见 §5.5。不取整时该误差为零，净值与名义本金规模无关。

#### （二）每日损益

$$
\boxed{\ \text{PnL}_t = N_{t-1}\ \big[\ \text{settle\_exit}_t - \text{settle}_{t-1}\ \big] \times 200\ }
$$

三个要点：

1. **持仓取 $N_{t-1}$**，即昨日收盘建立的头寸——它承担了从昨日收盘到今日收盘的全部价格变动。
2. **价差的两端是同一份合约**。$\text{settle}_{t-1}$ 是昨日持有合约 $\text{code}_{t-1}$ 的昨日结算价；$\text{settle\_exit}_t$ 定义为**同一份合约 $\text{code}_{t-1}$ 的今日结算价**。非换月日它等于 $\text{settle}_t$；换月日则是旧合约的今日结算价（该合约当天仍在交易）。该列由 `build_schedule` 一并给出，其构造与跨合约做价差的后果见 §2.3。
3. **换月动作本身不产生损益**：今日以 $\text{settle\_exit}_t$ 平掉旧合约、以 $\text{settle}_t$ 建立新合约，两者的价差（新旧合约的基差落差）不进损益表，只改变后续的基差水平。

#### （三）名义基数与净值

（一）中的"名义本金"实为**当日建仓所用的名义基数** $M_t$，由 `notional_mode` 决定：

| `notional_mode` | $M_t$ | 含义 |
| --------------- | ------- | ------ |
| `"leg"`（默认）   | $M_t = M_0\cdot\text{NAV}_{I_k - 1}$，$I_k$ 为当腿发行日 | 每只雪球发行时按当时净值重置名义、**腿内冻结**。已实现盈亏闲置到下一只雪球建仓时才投入 |
| `"daily"`         | $M_t = M_0 \cdot \text{NAV}_t$                            | 名义逐日随净值缩放，即净值化基金的运作方式（$\text{NAV}_t$ 精确取"盯市后、付费前"，见 §6） |
| `"fixed"`         | $M_t \equiv M_0$                                           | 名义恒定，盈亏不滚入仓位规模 |

三种模式下净值公式**完全相同**——损益按日累加、扣除手续费，除以期初名义 $M_0$：

$$
\text{NAV}_T = 1 + \frac{1}{M_0}\sum_{t} \big(\text{PnL}_t - \text{fee}_t\big)
$$

其中 $\text{fee}_t = \text{当日单边成交名义额} \times \texttt{fee\_rate}$（默认万五），成交价基准与换仓口径一致（见 §6）。

把（一）代入（二）可看清三种口径的差别。忽略取整，由 $\Delta_t$ 的定义有 $N_{t-1} \times 200 = \Delta_{t-1} M_{t-1} / \text{settle}_{t-1}$，故

$$
\frac{\text{PnL}_t}{M_0} = \Delta_{t-1}\,\frac{M_{t-1}}{M_0}\cdot\frac{\text{settle\_exit}_t - \text{settle}_{t-1}}{\text{settle}_{t-1}} = \Delta_{t-1}\,\frac{M_{t-1}}{M_0}\, r_t
$$

**`"fixed"`**：$M_{t-1}/M_0 \equiv 1$，故

$$
\text{NAV}_T = 1 + \sum_t \Delta_{t-1}\, r_t
$$

即**净值是 delta 加权的期货日收益的算术和**。每日按当日价格重新调整手数以维持目标敞口，但盈亏不滚入下一期的仓位规模。

**`"daily"`**：$M_{t-1}/M_0 = \text{NAV}_{t-1}$，代回即得递推

$$
\text{NAV}_t = \text{NAV}_{t-1}\big(1 + \Delta_{t-1} r_t\big) \qquad\Longrightarrow\qquad \text{NAV}_T = \prod_t \big(1 + \Delta_{t-1} r_t\big)
$$

**净值自动变为连乘，无需另改净值公式**——复利性质完全由名义基数的缩放产生。

**`"leg"`（默认）**：$M_{t}/M_0$ 在第 $k$ 腿存续期内冻结为常数 $\text{NAV}_{I_k-1}$，故净值在腿内是算术累计、腿间连乘：

$$
\text{NAV}_t = \text{NAV}_{I_k-1}\Big(1 + \sum_{s\in[I_k,\,t]} \Delta_{s-1} r_s\Big),\qquad
\text{NAV}_T = \prod_k \Big(1 + \sum_{s\in\text{腿}k} \Delta_{s-1} r_s\Big)
$$

对应的叙事是**复制一只名义固定的虚拟雪球**：$\Delta$ 乘的是该腿发行时确定的名义，腿内的对冲盈亏是自有资金、不改变对冲头寸规模。它是前两者之间的插值——重置点只有首日即退化为 `"fixed"`，重置点越密越接近 `"daily"`。

基数取**前一交易日收盘净值**而非当日盯市净值：默认 `reissue_lag_days=5` 时腿间有空仓（无持仓、无成交，净值不动），两者恒等；`reissue_lag_days=0` 时前者能让"各腿收益连乘 $=$ 全周期总收益"精确成立。

`"leg"` 与 `"daily"` 的共同代价是净值成为一条**递推**：$\text{PnL}_t$ 依赖历史净值，故不能先算完整条 `pnl` 再 `cumsum`，必须逐日推进（实现见 §6）。

三者的关系为 $\sum r_t \approx \ln\prod(1+r_t) + \tfrac12\sum r_t^2$：波动拖累使复利更低，漂移的凸性使复利更高，**孰大孰小取决于区间内漂移与波动的相对大小，不能一概而论**。以 2018 年中证500 为例：几何跌幅 −34.18%（对数 −0.4181），当年方差项之半为 2.82pp，两者相加 −39.00%，与实际算术和 −38.97% 吻合。

**如何选**。`"leg"` 为默认：与"复制一只名义固定的虚拟雪球"的建模叙事一致，且腿内不因盈亏改变头寸规模，执行上也最直白。`"daily"` 更贴近净值化**基金**的运作：客户按净值申赎，管理人收盘时按当前 AUM 的 $\Delta_t$ 比例配敞口，账上不留闲置的已实现盈亏；代价是腿内净值涨跌会同步放大/缩小头寸。`"fixed"` 则换来一组精确成立的加法恒等式（净值与名义规模、与路径顺序均无关；§8 的各项损益归因可精确相加），是更干净的**归因**透镜。三者并存、同时报告，不是三选一。

⚠️ 切换口径会**同时**改变累计方式与年化定义（`"fixed"` 线性，`"leg"` / `"daily"` 几何），可能出现"总收益升高而年化数字下降"的表象，比较时须同口径对同口径。§8 的三条对照净值随 `notional_mode` 统一切换（`"leg"` 下三条曲线共用同一套腿边界，即同一份资金注入时间表），以保证同图可比。

#### （四）滚动发行如何接入

以上是单只雪球的机制。滚动发行有两种模式（`n_slots` 控制，默认为 4 槽位 ladder；本节按单链条行文，ladder = 多条错峰的单链条 + 策略级聚合记账，见 `backtest.py` docstring）。**顺序滚动**（sequential，`n_slots=1`）指任一时点至多一只虚拟雪球存续：第 $k$ 只在 $E_k$ 收盘终止（敲出或到期），第 $k+1$ 只在 $E_k$ 之后第 `reissue_lag_days`（默认 5）个交易日（`monday_issue=True` 时再落到下一个周一网格日）发行，期初价取发行日收盘。间隔期 $[E_k,\ I_{k+1})$（含终止日）敞口为 0（空仓）、票息计提暂停。

间隔的动机是**执行可行性**：敲出与否要到收盘才能确认，"终止当日以当日收盘价发行新腿并建仓"在时间顺序上不可交易；隔开若干交易日后，平旧仓与建新仓的决策信息都在执行窗口之前落定。`reissue_lag_days=0` 退回"终止当日接续、无空仓日"的口径。

对上面的日循环而言，滚动只改变 $\Delta_t$ 这一个输入的来源：终止日至下一腿发行前 $\Delta_t = 0$，发行日起取新腿的 delta。损益记账、换月处理、净值累加均不受影响，仍是一条连续序列（实现见 §7.2）。

回测覆盖到数据末端。末腿若在末端仍未了结（既未敲出也未到期），则在末端**截断**，记为情形 0，并按记账约定于当日平仓——这是记账动作，不是合约事件，该腿的实际结局在数据外未知，其损益缺口不代表最终盈亏。截断腿的条款仍按**完整存续期**构造（定价需要完整的敲出观察日程，少几次观察就是另一只雪球、票息也不同），为此用"真实交易日历 + 末端之后的合成工作日"生成条款；合成日按周一至周五排布、不含节假日，只影响末端之后观察日的具体日期，且不参与任何取价。配置项 `allow_truncated_leg=False` 可退回"装不下完整一只就停止发行"的行为。

**对照序列**为跨腿累计的名义票息计提，即同期持续滚动申购雪球所能计提的票息。其口径必须与 `notional_mode` 保持一致：

| 口径 | 票息对照线 |
| ------ | ------------ |
| `"fixed"`           | $\displaystyle\sum_{j\ \text{已完成}} C_j^*\tau_j + C_k^*\tau_k(t)$ |
| `"leg"` / `"daily"` | $\displaystyle\prod_{j\ \text{已完成}}\big(1 + C_j^*\tau_j\big)\cdot\big(1 + C_k^*\tau_k(t)\big) - 1$ |

后者即"客户滚动申购、本息滚入下一只"的净值。`"leg"` 与 `"daily"` 共用同一条：雪球票息在自己的名义上按 $\tau$ 线性计提、只在腿间滚入，本就没有腿内复利，故两种口径下的票息线相同。

**两端必须同口径**：若只把对冲端改成复利而票息端仍是算术和，§8 的覆盖率会被系统性高估。

### 0.2 本框架不做的事

以下缺省会系统性影响净值水平，解读结果时须计入：

- 交易成本仅计**手续费**（单边、按成交名义额的比例，`fee_rate` 默认万五，可设 0 退回免费用口径），无冲击成本；
- 持仓为**连续合约数**（编指数口径，`round_lots=False` 默认），无整数手颗粒度约束；`round_lots=True` 可切到执行层口径；
- 无保证金占用与现金管理收益；
- ladder 的槽位数默认 4 只并存、初始按周错峰（`n_slots` / `slot_stagger_weeks` 可调）；4 只腿初始集中在首月发行，**宽 vintage 分散（发行日横跨整个 tenor）不在默认配置内**——持续熊市中组合尾部行为接近单只雪球，入场敏感性问题用"多起点各跑一遍"回答。

名义本金是否随净值复利**不属于缺省**，由 `notional_mode` 显式控制（见 §0.1（三））：`"leg"`（默认）每腿重置、腿内算术腿间连乘；`"daily"` 名义逐日缩放、净值逐日连乘；`"fixed"` 固定名义、净值为算术和。

### 0.4 全局口径约定

四条约定贯穿全部代码，是各模块能对齐、两引擎能互验的前提：

| 口径                    | 取值                       | 依据                                                                                              |
| ----------------------- | -------------------------- | ------------------------------------------------------------------------------------------------- |
| **定价口径**      | 凭证口径，发行日$PV = 1$ | 客户交付本金、到期还本付息，票息含本金的资金成本                                                  |
| **扩散时钟**      | 每交易日$dt = 1/252$     | 波动率由"日收益标准差$\times\sqrt{252}$"估出，$\sigma/\sqrt{252}$ 为与之匹配的单日标准差      |
| **贴现/计息时钟** | 自然日 / 365               | 贴现因子与票息计提按日历天数，周末与长假不能丢                                                    |
| **净值口径**      | 由`notional_mode` 选定   | `"leg"`（默认）：每腿重置、腿内算术腿间连乘；`"daily"`：逐日缩放、逐日连乘；`"fixed"`：固定名义、算术和。差异为$\sum r_t \approx \ln\prod(1+r_t) + \tfrac12\sum r_t^2$ |

扩散与贴现使用**两套时钟**是刻意设计，各自与其参数的估计口径一致。MC 与 PDE 均严格遵守；若不一致，两引擎将出现约 10bp 的系统性口径差，互验即失去意义。

**判定惯例**：敲出 = 观察日收盘 $\ge$ 敲出线；敲入 = 交易日收盘 $<$ 敲入线（严格小于）。均为收盘判定，非盘中触及。约定写在 `snowball_contract.py` 文件头，`payoff.py` 与 `pde_engine.py` 按同一份文字实现。

## 2. 期货合约链

`futures_chain.py` 回答：**任意交易日 t，按给定规则应持有哪个合约？今天是否换月？**

### 2.1 核心抽象：槽位（slot）

中金所的挂牌规则动态维持"当月、次月、随后两个季月"结构：任意时刻在市合约恰为四个，每有一个摘牌即上市一个补位。把当日在市合约按到期年月升序排列，位置即槽位：

```
slot 0 = 当月    slot 1 = 次月    slot 2 = 当季    slot 3 = 下季
```

"持有当季"即定义为"每天持有落在 slot 2 上的合约"。该定义把"选哪个合约"从需要维护状态的问题变为每日独立可算的纯函数，回测无需记录"上次换到哪了"。

> 注意：当季 $\ne$ "最近到期的季月合约"。季月合约一生经过下季→当季→次月→当月四个槽位，每 3 个月中有 2 个月最近的季月合约正占据近端槽位。正确定义是按到期排序后的第 3、4 位。

**合约寿命由代码 `ICYYMM` 的 MM 决定**（139 个合约全部验证通过，仅 IC 上市首日的 4 个首批合约无前序合约可循）：

- MM $\notin$ {3,6,9,12}：在 YYMM 前移 **2 个月**的合约摘牌后首个交易日上市，寿命约 2 个月（实测均值 58 个自然日），一生只经过次月→当月两个槽位；
- MM $\in$ {3,6,9,12}：在 YYMM 前移 **8 个月**的合约摘牌后首个交易日上市，寿命约 8 个月（实测均值 240 个自然日），走完全部四个槽位。

### 2.2 换月的两种生成规则

全部换月日期在回测开始前即可确定，`build_schedule()` 一次性算出整条日历：

| 规则        | 换月日                                    | 换月时距合约自身到期 | 实测频率   |
| ----------- | ----------------------------------------- | -------------------- | ---------- |
| 当月 / 次月 | 持有合约最后交易日 −`roll_buffer_days` | 5 个交易日           | 12.1 次/年 |
| 当季 / 下季 | 新季月合约上市当日（挂牌结构平移）        | 约 2 个月            | 4.0 次/年  |

季月规则不涉及临近交割：标签在合约还剩两个多月时即迁移走。`roll_buffer_days`（默认 5）实际只对"当月"规则生效。

**最后交易日的确定**：已到期合约直接取"数据中最后一次出现的日期"，自动吸收节假日顺延；仅数据末端仍存续的合约用第三个周五估计兜底。硬编码"第三个周五"会在多个节假日顺延的月份出错。

### 2.3 对外接口

| 方法                                     | 用途                                                         |
| ---------------------------------------- | ------------------------------------------------------------ |
| `FuturesChain(md, roll_buffer_days=5)` | 构造。预计算合约信息表、每日槽位、结算价宽表                 |
| `contract_on(date, rule)`              | 该日应持有的合约代码                                         |
| `build_schedule(rule)`                 | **给 hedger 层的主接口**，见下                         |
| `quarterly_for_repo(date)`             | 给 market_params 的接口：当季合约的 (代码, 结算价, 剩余年限) |
| `settle(date, code)`                   | 结算价查询                                                   |

`build_schedule(rule)` 返回整条持仓日历，五列：`code` / `settle` / `close` / `is_roll` / `settle_exit`。其中固化了持仓的时间约定：**日期 t 的 `code` 指"t 日结算时刻起持有、到 t+1 日结算"的合约**，而 `settle_exit` 是**自 t−1 日起持有的那个合约**（即 $\text{code}_{t-1}$）在 t 日的结算价——非换月日等于 `settle`，换月日为旧合约当日结算价。于是逐日损益

$$
\text{PnL}_t = N_{t-1}\big[\text{settle\_exit}_t - \text{settle}_{t-1}\big]\times 200
$$

**价差永远在同一合约内部计算**。这一条直接决定 hedger 层的记账正确性：若跨合约做价差，换月当天会产生虚假盈亏（实测某次换月新旧合约价差 68.4 点，在 1 亿名义、79 手持仓下即虚增约 108 万元），一年 12 次换月足以使净值曲线失效。

**合约选择做成回测参数**（`当月`/`次月`/`当季`/`下季`）。数据事实：四个槽位的 `settle/spot − 1` 在样本期内恒序为 下季 < 当季 < 次月 < 当月 < 0；持仓量与成交量在新上市合约的首日显著低于其余合约（如 2021-07-19 上市的 IC2203 首日持仓 2465 手，同日其余合约为 6.6 万~10.1 万手）。

## 3. 市场参数

`market_params.py` 估计定价所需的两个不可直接观测的参数（$S$ 与 $r$ 直接来自数据层）。

**入口**：`build_market_params(md, chain) -> MarketParams`。两条序列在回测开始前**一次性算好全部交易日**，回测中每日只做查表，不重复计算。

### 3.1 repo

由期货价格反推的风险中性漂移：

$$
\text{repo}_t = r - q = \frac{\ln(F_t / S_t)}{\tau_t}
$$

$F$ 取**当季槽位**合约结算价，$\tau$ 为其剩余期限（自然日/365，与贴现口径一致）；先按 $\pm 30\%$ 截断，再取 20 日滚动均值。

**为何取当季槽位**：该槽位剩余期限实测恒定在 1.8~5.1 个月，$\ln(F/S)/\tau$ 的分母不会趋零，无需额外剔除临近交割时段。这是槽位定义带来的直接简化。

**为何先截断再平滑**：顺序相反时，单个异常值会被平均进随后 20 天的平滑值，污染扩散；先截断可将影响限制在单点。实测 190 次截断中绝大多数出现在 2015-2016 年股指期货限仓时期，2017 年后不触发。

**为何平滑**：delta 每日重算，repo 逐日波动会直接传导为仓位波动。20 日窗口为跟随性与稳定性的折中；窗口选择的影响见 §5.5。

repo 为负对应 $F < S$、$q > r$。分年度实测值：

| 时期      | 年均 repo                |
| --------- | ------------------------ |
| 2015-2016 | −23% 左右，大量触及截断 |
| 2018-2021 | −7% ~ −12%             |
| 2022-2023 | −5.8% → −2.2%         |
| 2025-2026 | −10% → −7.8%          |

### 3.2 vol

指数对数收益的 250 日滚动标准差，年化 $\times\sqrt{252}$。

**实现要点**：在指数的**全部历史（2013 年起）**上计算，算完再对齐到共同交易日。若先对齐再滚动，共同日历的前 250 天将因预热不足变为 NaN，损失 2015-2016 的回测区间。这是数据层"不截断指数历史"的用途。

**已声明的建模假设**：模型采用**单一常数波动率**，未引入波动率期限结构或偏斜，亦未使用场内期权隐含波动率。雪球的敲入线位于期初价的 70~80%，属深度虚值看跌区域，该区域的隐含波动率与 ATM 一般不同；本模型不刻画这一差异。

### 3.3 取数接口

```python
params = build_market_params(md, chain)
snap = params.snapshot("2021-06-15")   # -> MarketSnapshot
# snap.s / snap.r / snap.repo / snap.sigma / snap.q
```

`MarketSnapshot` 的四个字段 $(s, r, \text{repo}, \sigma)$ 即定价层的全部输入。这一个接口承载核心约定：**票息在发行日锁定、delta 每日重算**——两者在代码上是同一个调用，区别仅在传入的日期。

`snapshot()` 内置 fail-fast：预热未完成的日期（repo 前 20 日为 NaN）直接报错并告知首个可用日，防止 NaN 流入定价器产出无效净值。

## 4. 条款定义

**构造**：`snowball_contract.make_snowball(calendar, issue_date, s0, ki_pct, ko_pct, tenor_months, lockup_months) -> SnowballTerms`

本模块只描述条款，不含计算逻辑。MC 与 PDE 共享同一份条款对象，以排除"两个引擎各写一套观察逻辑、结果不符却归因于数值误差"这一类缺陷。

**参数映射**：`lockup_months=2` 对应"首次敲出观察在第 3 个月"（构造器逻辑为首次观察在第 `lockup+1` 个月）。

**观察日历生成**：

- **敲出观察日**：第 `lockup+1` 至 `tenor` 个月的"对日"，用 `pd.DateOffset(months=k)` 生成目标日（自动处理月末收缩，如 8/31 + 6 个月 = 2/28），再顺延至不早于目标日的第一个交易日。**最后一次观察日即到期日**——这是"情形 3"（敲入未敲出且 $S_T \ge S_0$）非空的前提：仅当敲出线 $> 100\%$ 时该情形可发生。
- **敲入观察日**：发行日**次日**起至到期日的全部交易日（发行日不观察，$S_0$ 定义为发行日收盘）。

**入口校验**：发行日须为交易日、$0 <$ 敲入 $<$ 敲出、锁定期 $<$ 存续期、到期不得超出日历（回测层据此判断何时停止发行新雪球）。

**关键属性**：

| 属性 / 方法                 | 用途                                                       |
| --------------------------- | ---------------------------------------------------------- |
| `ki_level` / `ko_level` | 百分比 × 期初价 → 绝对点位                               |
| `tau(date)`               | 发行日到某日的年化时长（自然日/365），票息计提与贴现共用   |
| `ko_obs_taus`             | 各观察日的$\tau$，敲出兑付 $1 + C\tau$ 直接查表        |
| `sim_grid`                | 完整模拟网格 = 发行日 + 全部敲入观察日                     |
| `grid_from(value_date)`   | **存续期估值的剩余网格** = 估值日 + 其后的敲入观察日 |
| `with_coupon(c)`          | 填入反解出的票息，返回新对象                               |

`frozen=True` 配合 `with_coupon` 返回新对象，使"发行日锁定的条款在存续期内被修改"在语言层面不可能发生。

## 5. 定价

### 5.1 统一门面

`pricer.py` 对外提供三个动作，两引擎共用同一套签名，切换引擎只改 `method` 字符串：

```python
c = solve_coupon(terms, snap, method="pde", n_space=601)   # 发行日反解票息
t = terms.with_coupon(c)
v = value(terms, snap, value_date, knocked_in, method)     # 任意日估值
d = delta(terms, snap, value_date, knocked_in, method)     # 任意日 delta
```

PDE 的数值参数（`n_space` / `theta` / `rannacher` / `ki_node`）经 `**pde_kw` 透传；`method="mc"` 时误传这些参数会明确报错，避免被静默吞掉。

**单位约定**：PV 以名义本金 $=1$ 计；`delta` 返回 $\partial PV/\partial S$（每指数点）。敞口比例 = 返回值 $\times s_0$。

**反解票息无需迭代**。`payoff.py` 保持了 $PV(C) = A + B\,C$ 的严格线性（见 §5.2 的分解表），故两次求值即可精确解出：

$$
C^* = \frac{1 - PV(0)}{PV(1) - PV(0)}
$$

对 MC 而言，同一批路径计算两个端点可使噪声在分子分母间同源相消。

### 5.2 MC 引擎

**`mc_engine.simulate_relative_paths(mu, sigma, n_steps, n_paths, seed, antithetic)`**

只生成**初值为 1 的相对路径**。GBM 对初值乘法齐次，随机部分与 $S_0$ 无关，调用方乘以现价得到价格路径。两个结果：

1. **delta 的公共随机数（CRN）自动成立**：$(s \pm h)\cdot\text{rel}$ 是同一数组的两次缩放，两次估值的噪声完全同源，差分时相消，且省去第二次模拟；
2. 同 `(seed, n_steps, n_paths)` 必产出同一数组，结果可复现。

采用精确离散化（对 $\log S$ 累加 $(\mu-\sigma^2/2)dt + \sigma\sqrt{dt}\,Z$，非 Euler 近似，日频下无离散化偏差）与对偶变量法（前一半用 $Z$、后一半用 $-Z$）。

**`payoff.evaluate_paths(terms, paths, value_date, knocked_in) -> PayoffResult`**

逐条路径判定五种情形。**输出保持对票息线性**——交出三个数组而非直接算出兑付金额：

| 情形               | `fixed`                     | `accrual`            | `pay_tau`            |
| ------------------ | ----------------------------- | ---------------------- | ---------------------- |
| 1 / 5 敲出         | 1                             | $\tau_{\text{敲出}}$ | $\tau_{\text{敲出}}$ |
| 2 未敲入未敲出到期 | 1                             | $T$                  | $T$                  |
| 3 / 4 敲入未敲出   | $1 + \min(S_T/S_0 - 1,\,0)$ | **0**            | $T$                  |

兑付 $=$ `fixed` $+\ C\times$ `accrual`。若直接算出金额，§5.1 的线性结构即失效。

向量化实现要点：敲出用 `paths[:, ko_pos] >= ko_level` 加 `argmax` 取首个命中；敲入用 `paths[:, 1:] < ki_level`（列 0 为估值日，排除在外，对应"发行日/估值日不观察"）；**敲出优先是结构性保证**——敲出分支不参考敲入标志，`ki_before_ko` 仅用于区分情形 1 与 5 的标签，不影响现金流。

时间基准分离：`pay_tau` / `accrual` 自发行日起算（合同口径），`valuation_tau` 记录估值日时点，贴现只贴剩余时间。

> **复用**：`evaluate_paths` 的输入只是"列与网格对齐的价格矩阵"，不区分模拟路径与真实历史路径。回测层判定虚拟雪球实际是否敲入敲出时复用同一函数，使模拟与实盘判定不可能出现标准分叉。

> **工程约束**：MC 引擎实体化 `(路径数 × 步数)` 矩阵且缩放时再复制一份，12 个月雪球每 10 万条路径峰值约 400MB。提高有效样本应增加**种子数**而非路径数。

### 5.3 PDE 引擎

**`pde_engine.solve_curves(terms, snap, coupon, value_date, ...) -> PDECurves`**

雪球虽路径依赖，但**只依赖"是否已敲入"这一个布尔状态**，故拆成两层价值函数，在同一 $(S,t)$ 网格上同步反向推进：

$$
\frac{\partial V}{\partial \tau} = \frac{\sigma^2}{2}\frac{\partial^2 V}{\partial x^2} + \left(\text{repo} - \frac{\sigma^2}{2}\right)\frac{\partial V}{\partial x} - rV, \qquad x = \ln S
$$

两层通过**区域赋值**耦合（每个时间步 = 一个交易日）：

- 每交易日（日频敲入观察）：$S \le KI$ 区域令 $V_{out} \leftarrow V_{in}$
- 每敲出观察日（月频）：$S \ge KO$ 区域令两层同时 $\leftarrow 1 + C\tau$
- 到期：$V_{in} \leftarrow \min(S_T/S_0,\,1)$，$V_{out} \leftarrow 1 + CT$

> **为何用区域赋值而非在 KI 处设 Dirichlet 边界**：将求解域截至 $[KI, S_{max}]$ 等价于把敲入改为**连续观察**——单日扩散中触及 KI 的路径全部被吸收。而合约按每日收盘判定，日内跌破再收回不构成敲入。区域赋值与离散观察一致：单日扩散对全部落点积分，落在 $S \le KI$ 的部分接 $V_{in}$，其余接 $V_{out}$。

**输出**：`PDECurves` 含估值日的**四条曲线**——$V_{out}(S)$、$V_{in}(S)$ 及各自的 delta。查询用 `.value(spot, knocked_in)` / `.delta(spot, knocked_in)` 插值读数。

这是 PDE 相对 MC 的结构性差异：**MC 每次模拟只回答"这一个现价的价值"，PDE 一次倒推回答"所有现价的价值"，delta 是曲线斜率，无随机噪声、无额外成本**。实测两年期合约单次求解 61 ms（`n_space=601`）/ 78 ms（`n_space=1201`），含整条 delta 曲线；MC 同等 delta（10 万路径）1695 ms。逐日重算 delta 的全周期回测因此可行。

**数值处理**（四项，均为标准手法）：

| 处理             | 作用                                                                                                                                         |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 网格对齐         | 调整$dx$ 使 $\ln(KI)$、$\ln(KO)$ 恰落在节点上                                                                                          |
| 障碍节点单元平均 | 敲出在$S=KO$ 处为 $O(1)$ 跳变，点赋值仅一阶收敛，取左右极限半和以恢复二阶                                                                |
| Rannacher 起步   | 间断（终值、每个敲出观察日）后的`RANNACHER`（=2）个交易日区间，各细分为 `RANNACHER_SUBSTEPS` 个全隐式子步，兼顾 L-稳定阻尼与二阶时间精度 |
| 敲入线处单边差分 | $V_{out}$ 在 KI 处有真实跳变，跨越间断的中心差分给出 $(\text{跳变})/(2dx)$ 的伪 delta；未敲入头寸只在 $S > KI$ 被查询，故取上侧导数    |

**`RANNACHER_SUBSTEPS` 是回测耗时的主要驱动**。单次求解的三对角求解次数为

$$
n_{\text{steps}} + (1 + n_{\text{剩余敲出观察日}}) \times \texttt{RANNACHER} \times (\texttt{SUBSTEPS} - 1)
$$

两年期合约上第二项占 60~70%。精度代价（对 §5.4 解析基准的 delta 偏差）实测为 16 → +0.04pt、8 → +0.15pt、4 → +0.37pt。**默认取 8**：0.15pt 远低于回测中其他误差源（1 亿名义下 IC 手数取整即 0.67pt），而耗时较 16 减半。

**可达状态空间**：`PDECurves` 在全域有数值，但回测可达的状态为"未敲入 $\times\ S > KI$" $\cup$ "已敲入 $\times$ 全域"。$V_{out}(S < KI)$ 对应"盘中已破线、尚未收盘确认"的中间态，按收盘判定状态后不会被查询。

### 5.4 双引擎交叉验证

两个引擎彼此独立（MC：路径模拟 + 五情形判定；PDE：两层反向推进 + 区域赋值），共享的只有条款对象与市场快照。但两者互比不符时无法判定哪一侧有误，故先构造**有闭式解的退化合约**作为基准：敲入线设至极低（永不敲入）且只保留 2 个敲出观察日，雪球退化为纯数字期权

$$
V(S) = D_1 A_1 P + D_2 A_2 (1-P), \qquad P = \Phi\!\left(\frac{\ln(S/KO) + (\text{repo} - \sigma^2/2)\Delta t}{\sigma\sqrt{\Delta t}}\right)
$$

估值日取在观察日前 3 个交易日——此时价值函数在敲出线附近尚未被扩散抹平，为离散化误差最大的位置。

**当前结果**（随机抽取发行日 × 条款，MC 用多种子均值，判据为 $|z| < 3$ 或差在容忍度内）：

| 项目     | 结果                                                   |
| -------- | ------------------------------------------------------ |
| 解析基准 | PDE 偏离 0.08pt，MC 偏离 0.05pt                        |
| 票息     | 相对差均值 0.44%、最大 1.11%                           |
| delta    | 绝对差均值 0.28pt、最大 0.97pt（未敲入/已敲入各 5 例） |

**该基准曾定位出一处实现缺陷**。原实现在每个间断后使用 4 个**整日**全隐式步；全隐式仅一阶时间精度，当估值日距观察日只有数步时这些步全为全隐式，误差无从摊薄，在"现价位于敲出线上方、距观察日 3 个交易日"的情形下产生 2 个 delta 敞口百分点的偏差（解析 −13.55%，错误实现 −11.47%）。定位过程：误差对 `theta`、`rannacher`、`n_space` 均不敏感（网格 2401→9601 无变化），排除振荡与空间精度；而 `rannacher` 由 4→2→1→0 时误差单调从 +2.09 变至 −0.69，指向全隐式步本身。改为标准配方（间断后细分为多个隐式子步）后，同一情形 PDE 给出 −13.52%，与解析（−13.55%）和 MC（−13.54%）一致；退化债券的解析误差亦从 3.2e-07 降至 1.3e-08。

**另一处为验证方法本身的错误**：MC 的 delta 是 $\pm 1\%$ 扰动的**割线**斜率，PDE 的 `delta()` 是网格求导的**切线**斜率，在障碍附近曲率大的位置两者本就不同（定义不同，非误差）。对齐口径后最大差由 1.87pt 降至 0.97pt。**回测使用切线 delta**——它是 $\partial V/\partial S$ 的直接估计。

**已知残差**。隔离测试显示：敲入概率为 0 时两引擎一致到 **0.0bp**（说明敲出、贴现、日历、票息计提全部对齐），残差随敲入概率线性增长，敲入概率 0.39 时约 +19bp，来源为 `apply_ki` 的日度区域赋值（每交易日施加一次，约 250 次）。`KI_NODE` 参数的三种约定（`out`/`avg`/`in`）互为上下界，Richardson 外推收敛到同一极限，故此残差为真实、有界、可量化的系统性差异，量级为票息相对差 0.05%~1.1%。

### 5.5 数值误差的量级

上述残差须与三项实测量比较：

**（一）MC 自身噪声**。delta 差异均值 0.28pt，MC 换种子噪声均值 0.80pt。绝对差最大的案例（0.97pt）恰为 MC 噪声最大的案例（$\sigma$ = 2.25pt），$z$ 仅 −1.06。

**（二）执行颗粒度**。IC 乘数 200 元/点，仓位只能取整数手。以敞口 82%、指数 6664 点计：

| 名义本金 | 理论手数 | 取整误差上限      |
| -------- | -------- | ----------------- |
| 0.2 亿   | 12.30    | 3.33 个敞口百分点 |
| 1 亿     | 61.52    | 0.67 个敞口百分点 |
| 5 亿     | 307.62   | 0.13 个敞口百分点 |

**（三）参数口径**。同一份代码、同一引擎，仅更换参数估计口径（两年期 70/103 @ 2021-06-15，基准票息 31.44%）：

| 参数选择              | repo / vol | 票息   | 相对基准          |
| --------------------- | ---------- | ------ | ----------------- |
| 波动率窗口 60 日      | 11.59%     | 11.44% | **−63.6%** |
| 波动率窗口 120 日     | 16.46%     | 22.80% | −27.5%           |
| 波动率窗口 500 日     | 21.80%     | 37.19% | +18.3%            |
| repo 平滑窗口 5 日    | −12.05%   | 37.87% | **+20.4%**  |
| repo 平滑窗口 120 日  | −11.24%   | 35.04% | +11.4%            |
| repo 改用下季合约反推 | −10.58%   | 32.91% | +4.7%             |

**工程结论**：数值误差（"是否正确求解了所写下的方程"）已量化，且比参数口径选择的影响小 1~2 个数量级。回测全程使用 PDE，票息与 delta 出自同一引擎、同一套离散化，误差一致而非随机，不随时间累积。

## 6. 对冲执行与记账

`hedger.py` 把定价层给出的 delta 序列转成 IC 期货持仓并逐日盯市。本模块不含定价逻辑，也不判断敲入敲出——只做"给定每日目标敞口，执行并记账"这一件事，因此可脱离雪球单独测试（内置自检用常数敞口序列）。

**主接口**：`run_hedge(delta, schedule, spot=None, notional=1e8, round_lots=False, delta_cap=None, close_at_end=True, fee_rate=5e-4, notional_mode="fixed", reset_dates=None) -> HedgeResult`

| 输入           | 内容                                                                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `delta`      | 每日目标**敞口比例**序列（如 0.82 = 82% 名义本金多头）                                                                                           |
| `schedule`   | `chain.build_schedule(rule)` 的产出                                                                                                                  |
| `spot`       | 可选。给出则额外产出方向性/基差损益分解                                                                                                                |
| `round_lots` | 是否取整到整数手。**默认 False（编指数口径）**：持仓为连续合约数，乘数在净值中自动消去；True 为执行层口径，引入 §5.5 所述颗粒度误差             |
| `delta_cap`  | 敞口对称截断至$[-\text{cap}, +\text{cap}]$，在取整之前施加。**只改变执行，不改变虚拟雪球本身**：票息仍按未截断条款反解，敲入敲出状态机不受影响 |
| `fee_rate`   | 单边手续费率（成交名义额的比例），默认万五（$5\times10^{-4}$）。设 0 退回免费用口径                                                                  |
| `notional_mode` | 建仓名义基数口径，见 §0.1（三）。`"fixed"` 恒为 `notional`；`"leg"` 在 `reset_dates` 换挡、窗口内冻结；`"daily"` 为 `notional` × 当日净值               |
| `reset_dates`   | **仅 `"leg"` 使用且必填**：基数重置日（回测中即各腿发行日）。本模块不感知"腿"的概念，重置点须由调用方给出；首日总是隐含的重置点               |

**日循环的四步顺序**（手续费引入"仓位→费→净值→仓位"的循环依赖，须按下列顺序拆开）：

1. **盯市**：$\text{nav}^{\text{mtm}} = \text{NAV}_{t-1} + \text{PnL}_t / M_0$，用昨仓结算；
2. **定仓位**：按口径确定 $M_t$（`daily`：$M_0\cdot\text{nav}^{\text{mtm}}$；`leg`：仅在重置日换为 $M_0\cdot\text{NAV}_{t-1}$，否则沿用；`fixed`：$M_0$），据此换算手数；
3. **计费**：按第 2 步产生的成交量计 $\text{fee}_t$；
4. **收盘**：$\text{NAV}_t = \text{nav}^{\text{mtm}} - \text{fee}_t / M_0$。

`daily` 下即**用"盯市后、付费前"的 AUM 定仓位**——这不是数学技巧，就是实际操作顺序：收盘先知道账户值多少钱，据此下单，再付这笔单子的费。`leg` 下取前一日收盘净值，理由见 §0.1（三）；因腿间空仓期无损益，$\text{NAV}_{t-1}$ 与 $\text{nav}^{\text{mtm}}$ 在重置日恒等。`daily` 列 `notional_t` 记录逐日的 $M_t$。复利口径下净值可被推至 0 以下（$\Delta$ 可超 100%），故基数换挡时对非正净值报错。

**四条会计规则**：

1. **价差永不跨合约**——用 §2.3 的 `settle_exit` 列，见该处的公式与后果说明。
2. **无前视偏差**——$\Delta_t$ 由 $t$ 日收盘价与 $t$ 日参数算出，只作用于 $t$ 之后的损益；$t$ 日的损益来自 $t-1$ 日建立的持仓。
3. **换月即全平全开**——换手统计上，换月日成交手数 $=$ $|$旧仓$|$ $+$ $|$新仓$|$，非换月日 $=$ $|$仓位变化$|$。
4. **手续费按单边成交名义额计**——$\text{fee}_t = \sum_{\text{各笔成交}} |\text{手数}| \times \text{成交价基准} \times 200 \times \texttt{fee\_rate}$。成交价基准与换仓口径一致：非换月日为 $\text{settle}_t$；换月日旧仓按 $\text{settle\_exit}_t$ 平仓、新仓按 $\text{settle}_t$ 开仓，分别计费。`daily` 中 `pnl` 保持**未扣费的盯市损益**（损益分解 `pnl_spot + pnl_basis = pnl` 的恒等式不变），`fee` / `cum_fee` 单列，净值 $= 1 + (\text{cum\_pnl} - \text{cum\_fee})/M_0$。

**归因用的归一化基数**（`HedgeResult.pnl_base`）：使 $(\text{PnL}_t - \text{fee}_t)/\text{pnl\_base}_t$ 为**该基数上的收益率**，从而三种口径下按各自方式累计都能精确还原净值（实测偏差在 $10^{-15}$ 量级）：

| 口径 | `pnl_base` | 还原方式 |
| ------ | ------------ | ---------- |
| `"fixed"` | $M_0$                             | $1+\text{cumsum}$ |
| `"leg"`   | 当腿的名义基数（即`notional_t`） | 腿内累加、腿间连乘 |
| `"daily"` | $M_0\cdot\text{NAV}_{t-1}$（前一日**收盘**净值） | $\text{cumprod}(1+\cdot)$ |

`"fixed"` / `"leg"` 下它就等于 `notional_t`（基数在窗口内恒定，无需错位）；`"daily"` 下与 `notional_t`（建仓基数，取盯市后、付费前）相差一个当日手续费——一个是归因口径，一个是建仓口径，用途不同。

**损益分解**。期货价格 $F = S + B$（$B$ 为基差），故

$$
\text{PnL}_t = N_{t-1}\big[(S_t - S_{t-1}) + (B_t - B_{t-1})\big]\times 200 = \text{pnl\_spot} + \text{pnl\_basis}
$$

其中 $B_t$ 用**旧合约**口径（$B_t = \text{settle\_exit}_t - S_t$），两项之和恒等于当日总损益（模块内对残差做断言）。

**跨模块的经济自洽性检验**：满仓多头（delta 恒为 1）持有一年，其基差损益应约等于同期年化 repo。这两个数字来自完全独立的代码路径——repo 由 `market_params` 从 $\ln(F/S)/\tau$ 估计并平滑，基差损益由 `hedger` 从逐日结算价记账推出。八年、两种合约规则的实测差异全部在 0.1~2pp 内（如 2018 年 +7.49% vs +7.56%，2021 年 +10.39% vs +10.33%）。若任一侧有误，两条独立路径不可能吻合。

## 7. 回测编排

`backtest.py` 把前三层串成完整链路。

### 7.1 单腿流程

1. 取发行日市场快照 → 2. 造条款、反解并锁定票息 → 3. 沿真实历史路径推进状态机 → 4. 逐日重算 delta。

**状态机**：敲入自发行日次日起、任一收盘 $<$ 敲入线即置位且不可逆（`cummax`）；敲出仅在观察日判定、$\ge$ 敲出线即终止。终止日 = 首个敲出日；否则为到期日；两者都未在数据内发生则为数据末端（截断，情形 0）。情形由状态机直接判定。

**冗余校验**：当整条路径在数据内可得时（到期日不晚于数据末端），把**同一条真实历史路径**喂给 `payoff.evaluate_paths` 独立判定一次，情形编号与终止时点不符即报错。回测状态机与定价所用判定规则由此保证同源——这是 §5.2 中 `evaluate_paths` "不区分模拟与真实路径"的用途。截断腿无完整路径，跳过该校验。

### 7.2 逐腿滚动

各腿 delta 序列与腿间空仓区段拼成一条连续序列，送入 `hedger` 得到连续净值。第 $k$ 腿的序列覆盖 $[I_k, E_k)$（**不含终止日**）；$[E_k,\ I_{k+1})$ 为空仓区段（delta 为 0，行归属于刚终止的腿，票息线定格）；末腿的终止日补一行 0（平仓）。空仓区段在**下一腿确认发行后**才落账，若下一腿未能发行（等待期越过区间末端），该区段丢弃、由末腿补行收尾，避免索引重复。

**逐腿损益归属**：`pnl[t]` 由 `lots[t-1]` 产生，故记给 $t-1$ 日的活跃腿；若按当日归组，腿切换日的损益会被错记到新腿。四项自检（单腿模式与分腿明细第 0 行一致、分腿之和等于算术归因和、腿衔接无缝、票息线单调）在两种 `notional_mode` 下均精确通过。

其中第二项在复利口径下的表述需要留意：各腿得到的是该腿期间的**算术收益率之和**，跨腿相加等于算术归因和，而非几何总收益——两者之差即 §8 的"复利交叉项"（`"fixed"` 下该项恒为 0，此时分腿之和就是全周期总收益）。

`"leg"` 口径下另有一条更强的恒等式：名义基数的换挡窗口与分腿归属窗口恰好重合（腿间空仓使切换日损益为 0），故**各腿收益连乘精确等于全周期总收益**，`__main__` 中对此单独断言。`reissue_lag_days=0` 时切换日损益不为 0，会留下一个跨界小残差。

### 7.3 接口

**`run_backtest(cfg) -> BacktestResult`**，函数进、结果对象出：

```python
from dataclasses import replace
r  = run_backtest()                                    # 全部默认
r  = run_backtest(start_date="2019-01-04")             # 关键字覆盖
r  = run_backtest(replace(cfg, hedge_contract="当季"))  # 显式配置
r  = run_backtest(max_legs=1)                          # 单只模式，便于逐腿诊断

results = sweep(BacktestConfig(), "delta_cap", [None, 2.0, 1.5, 1.0])
compare(results)                                       # -> 汇总对比表

compare(sweep(BacktestConfig(), "notional_mode", ["leg", "daily", "fixed"]))  # 三种净值口径
```

`BacktestConfig` 是 frozen dataclass，四组参数：回测区间与条款、市场参数估计口径、定价数值参数、对冲执行参数。改参数用 `dataclasses.replace`，不改文件。其中 `notional_mode` 默认 `"leg"`（见 §0.1（三））；`run_hedge` 作为底层原语则默认 `"fixed"`，以保持其独立自检的加法恒等式。`"leg"` 所需的 `reset_dates` 由本层用各腿发行日填入。

**缓存**：`_market_data` / `_chain` / `_params` 按参数缓存；`run_backtest` 的结果亦按 `cfg` 缓存（`BacktestConfig` 可哈希），重复运行同一配置为即时返回。换数据后调 `clear_cache()`。

**输出**。`BacktestResult.daily` 每日一行：`delta` / `notional_t` / `lots` / `pnl` / `fee` / `nav` / `spot` / `spot_ratio` / `knocked_in` / `coupon_line` / `repo` / `vol` / `pnl_spot` / `pnl_basis` / `leg` / `code` / `is_roll` / `traded_lots`；`legs` 每只雪球一行（发行日、终止日、期初价、票息、情形、存续年数、敲入日、该腿损益（已扣费）、该腿手续费与票息计提）。`BacktestResult.pnl_base` 给出 §6 所述的归因归一化基数。

**分腿归属口径**：盯市损益 `pnl[t]` 由 `lots[t-1]` 产生、记给 $t-1$ 日的活跃腿（见 §7.2）；手续费 `fee[t]` 由 $t$ 日的调仓产生（目标敞口来自当日活跃腿）、记给**当日**的腿——腿切换日的换仓费记给新腿。两项之和恒等于全周期净收益。

**耗时**：全周期回测的主要成本是逐日 PDE 求解。`n_space=601`（回测默认值，与 1201 的票息差异约 1bp）下，2018-01-02 至数据末端 2026-07-28（8.57 年、12 只雪球）实测约 90 秒。切换 `notional_mode` 不改变定价与 delta 序列（见 §0.3 的分层：名义本金从不进入定价层），故只是记账层重算，但由于结果按 `cfg` 缓存，每种口径仍各跑一次 PDE。

## 8. 结果分析

`analytics.py` 提供对照基准与统计量，使 notebook 只做调用与展示。

**对照基准**（`build_benchmarks(res)`）。两条基准与策略采用**同一净值口径**（随 `cfg.notional_mode` 一并切换），以保证同图可比：

| 曲线   | 构造方式                                                                             |
| ------ | ------------------------------------------------------------------------------------ |
| 策略   | 按虚拟雪球 delta 持有 IC                                                             |
| CSI500 | 指数现货多头（无手续费），经`analytics.accumulate_nav` 按与策略相同的口径累计：`"fixed"` 算术累计 $1+\sum r_t$、`"leg"` 腿内算术腿间连乘、`"daily"` 买入持有的几何净值 $\prod(1+r_t)$ |
| IC多头 | delta 恒为 1 的期货多头，走同一套`hedger` 记账（含换月、取整、手续费、名义口径、腿边界，均同策略） |

`"leg"` 口径下三条曲线**共用同一套腿边界**（`res.legs["issue_date"]`），即同一份资金注入时间表，否则曲线不可比。

**净值统计**（`nav_metrics` / `compare_navs`）：总收益、年化收益、年化超额、年化波动、夏普（无风险利率取区间 Shibor 1年均值）、卡玛、日胜率，以及最大回撤及其三个时点（前高日、谷底日、首次回到前高之日；未回到记"未修复"）。年化超额以 **CSI500 为基准**（`compare_navs(..., benchmark=...)` 可改），基准自身记为 NaN。

其中三项的定义随口径切换，由 `geometric` 参数控制（传 `res.cfg.compounding`，`"leg"` / `"daily"` 均为 True）：

| 指标     | `"fixed"`（算术）              | `"leg"` / `"daily"`（复利）          |
| -------- | ------------------------------ | ------------------------------------ |
| 日收益   | 净值一阶差分$\text{NAV}_t - \text{NAV}_{t-1}$ | 净值相对变化$\text{NAV}_t/\text{NAV}_{t-1} - 1$ |
| 年化收益 | 总收益$\div$ 年数            | $\text{NAV}_T^{1/\text{年数}} - 1$ |
| 年化波动 | 上述日收益的标准差$\times\sqrt{252}$ | 同左（用相对口径的日收益）        |

`"leg"` 下净值在腿内是**冻结基数上的算术累计**，故净值的相对变化并不严格等于"该基数上的收益率"（两者差一个 $\text{NAV}_t/M_t$ 的因子）。此处仍取净值相对变化——它就是投资者从一条公开净值曲线上能算出的日收益，与夏普、波动的通行定义一致；需要严格的基数收益时用 `pnl_base` 归一（见 §6）。

最大回撤在两种口径下都是 $\text{NAV}/\text{cummax}(\text{NAV}) - 1$，无需区分。

**策略统计**（`strategy_metrics`）：基准无对应项的策略特有指标。除"雪球只数""换月次数"等字面即明的项外，各项定义如下（年数一律取 $(\text{末日}-\text{首日})/365$）：

| 指标                        | 定义                                                                                                                                                               |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 方向性贡献 / 贴水(基差)贡献 | 逐日`pnl_spot` / `pnl_basis` $\div$ `pnl_base`（§6）后求和，即 §6 损益分解的两项累计（未扣费）                                                            |
| 手续费拖累 / 手续费年化     | 逐日`fee` $\div$ `pnl_base` 后求和（拖累以负号呈现）；年化为其 $\div$ 年数                                                                                   |
| 复利交叉项                  | 对冲端总收益减去上述三项之和。`"fixed"` 下恒为 0（此时三项精确相加即总收益）；`"leg"` / `"daily"` 下为算术归因和与几何总收益之差。**四项之和在三种口径下都精确等于对冲端总收益** |
| 贴水贡献年化                | 贴水贡献$\div$ 年数                                                                                                                                              |
| 贴水占比                    | 贴水贡献$\div$ **算术归因和**（= 方向性 + 贴水 − 手续费）。分母不取几何总收益，以保证与分子同口径；`"fixed"` 下算术归因和即对冲端总收益                       |
| 覆盖率(对冲/票息)           | 对冲端总收益$\div$ 票息计提总额。分母为 §0.1（四）的票息对照线终值，**与分子同 `notional_mode` 口径**（`"fixed"` 两侧皆算术、`"leg"` / `"daily"` 两侧皆复利）        |
| 覆盖率(年化)                | 对冲端年化$\div$ 票息年化（年化口径同上表）。**复利口径下应以此项为准**：两端皆为连乘序列时，总收益之比会被凸性严重扭曲——实测全周期 12 只腿、各腿票息累计约 20%，连乘后票息端总额达算术和的 2.3 倍，使 `"daily"` 下总收益之比从 0.55 掉到 0.28，而年化之比为 0.44。算术口径下年化只是同除年数，本项与上项恒等 |
| 平均 delta / 最大 delta     | 逐日**目标敞口比例**的均值 / 最大值。取的是经 `delta_cap` 截断后、取整前的目标值，非实际持仓手数换算回的敞口                                               |
| delta>100% 占比             | 目标敞口比例大于 1 的**交易日占比**（非时间加权）                                                                                                            |
| 已敲入天数占比              | 当日活跃腿处于已敲入状态的交易日占比                                                                                                                               |
| 敲出只数                    | 情形 1（敲出、此前未敲入）与情形 5（敲入后敲出）之和                                                                                                               |
| 敲入亏损只数                | 仅情形 4（敲入未敲出且$S_T < S_0$）。情形 3（敲入未敲出但 $S_T \ge S_0$，本金无损）不计入                                                                      |
| 平均票息                    | 各腿$C_j^*$ 的**简单算术平均**，不按存续期或名义加权                                                                                                       |
| 平均存续年数                | 各腿$\tau_j(E_j)$ 的简单平均；截断腿按其**可观测**存续期计，非合约存续期                                                                                   |
| 累计成交手数                | **单边**计数：换月日 $=$ $\lvert$旧仓$\rvert + \lvert$新仓$\rvert$，非换月日 $=$ $\lvert$仓位变化$\rvert$                                      |
| 年均换手率(倍)              | $\sum_t\left(\text{成交手数}_t \times \text{settle}_t \times 200 \big/ M_t\right) \big/ \text{年数}$，即单边成交名义额平均每年相当于名义基数的多少倍。此处按**当日**建仓基数 $M_t$ 归一（成交发生在当日），与上面按 `pnl_base` 归一的归因项口径不同 |

**分腿明细**（`leg_table`）：每只雪球一行的可读表格。

## 9. 使用方式与文件索引

主入口为 `notebooks/main_backtest.ipynb`，七节：条款与参数定义 → 市场数据与市场参数 → 定价（票息与 Delta 剖面）→ 全周期回测与净值对比 → 净值统计量 → 策略统计量与分腿明细 → 参数扫描（待办）。全部计算由 `src/` 完成，notebook 只负责调用与展示。

净值口径（`notional_mode`）贯穿 §0.1（三）、§6、§7、§8，改动集中在第 3~4 层：**第 0~2 层的八个文件不受影响**——定价为凭证口径 $PV=1$ 归一，票息只依赖条款与市场参数，delta 输出的是无量纲比例，名义本金从不进入定价层。

| 文件                         | 职责                 | 主要入口                                                             |
| ---------------------------- | -------------------- | -------------------------------------------------------------------- |
| `src/data_loader.py`       | 数据读取、清洗、校验 | `load_market_data()`                                               |
| `src/futures_chain.py`     | 合约选择、换月日历   | `FuturesChain` / `build_schedule()`                              |
